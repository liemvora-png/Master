# antislop audit 003 - 2026-11-20

Mode: AFTER (session choice). Read-only audit; nothing modified until approved numbers are fixed.

Scope audited: the progressive gallery image loading implementation on `fix/gallery-progressive-loading` (`public/assets/gallery.js`, `public/styles.css`, and `tests/gallery.test.mjs`).

Priority mapping: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

## Findings

1. **R-26 / Network Priority (LOW) - All offscreen previews load concurrently before tier advance.** On mobile devices with slower connections or data limits, rendering the full gallery list triggers simultaneous async decoding and network requests for all photos' preview images before upgrading visible ones.
   - Refinement option: Use an `IntersectionObserver` to trigger the progressive climb only as figures enter or near the viewport, saving bandwidth for photos the user never scrolls down to.

2. **C-4 / Resilience (LOW) - Static candidate width/height attributes during preload.** `candidate.width = 1200; candidate.height = 900;` in `preload()` hardcodes a 4:3 ratio for the off-DOM candidate image. While the DOM `<img>` uses `object-fit: cover` within `.gallery-photo-frame`, non-4:3 aspect ratio images decode under forced 4:3 dimensions in the off-DOM preloader.

## Verified passing (spot-checked)

- **R-02 (Copywriting)**: No em dashes (`—`) in gallery scripts or templates.
- **R-03 (Mobile Responsiveness)**: Clean multi-column to single-column reflow across viewports.
- **R-25 (Color Contrast)**: Frame and placeholder tokens maintain accessible contrast ratios in both light and dark themes.
- **R-26 (Interactive & State Transitions)**: Images are never dimmed or blurred; cached and preloaded images transition without hanging via `(image.complete && image.naturalWidth > 0)`.
- **C-1 & C-2 (Intentionality & Completeness)**: Failed intermediate tiers do not strand photos; the upgrade chain guarantees progression to the final full-resolution tier.
