# antislop audit 002 - 2026-11-02

Mode: AFTER (session override). Read-only audit; nothing modified until approved numbers are fixed.

Scope audited: the live `/news/` page (`public/news/index.html` on `origin/main`, rendered with `public/styles.css`). Reported because the page is unreadable for dark-mode visitors.

Priority mapping: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW.

## Findings

1. **R-25 (HIGH) - Body text invisible in dark mode.** The page hardcodes `color: #1c1e26` (near-black) while the shared `styles.css` paints `body` with `var(--paper)`, which is `#161814` (near-black) under `prefers-color-scheme: dark`. Measured contrast **1.08:1**. This is the reported unreadability.

2. **R-25 (HIGH) - Links and timestamps fail AA on dark.** Source links `#0b5cad` measure **2.68:1** and `time`/`.updated` `#5a5e6e` measure **2.78:1** against the dark background (both need 4.5:1). Both pass on the light paper, so only the dark theme breaks.

3. **R-34 (HIGH) - Light-only page; dark theme and saved theme ignored.** The inline palette works in exactly one theme. The page also never applies the site's persisted theme (`localStorage "theme"` -> `data-theme` set by `site.js`), so a manual theme choice on the main site does not carry to `/news/`. Fix: use the site tokens (`var(--ink)`, `var(--muted)`, `var(--line)`, `var(--olive)`, `var(--sans)`) and add a tiny pre-paint bootstrap that reads the stored theme.

4. **R-29 (LOW) - News page ignores the site's design system.** `system-ui` + blue `#0b5cad` vs the site's DM Sans/Playfair + paper/ink/olive identity; the page reads as a different site. Same fix as 1-3: inherit the tokens.

5. **R-02 (HIGH, content-owned) - Em dashes in digest text.** `—` appears throughout the digest body copy (e.g. "instructions — no gradient descent"). The text is produced by the news-digest pipeline, so the fix belongs to the generator/markdown content, not the page CSS. Flagging, not auto-fixing.
